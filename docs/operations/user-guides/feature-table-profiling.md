# 特徵表檢查工具

`scripts/profile_feature_table.py`：給一張 Hive 特徵表，用 Spark 算每一期、每一欄的統計量，產出一份 HTML 報告，標出要處理的欄位，附建議的處理方式。

> 它**只看、不改**：報告最後的〈行動建議總結〉把欄名整理成可以複製的清單，要怎麼用由你決定。報告不提框架的設定。
>
> 設計文件：`docs/notes/2026-10-15-feature-table-profiling-design.md`（規則、門檻、報告編排都以它為準）。

**這一版有兩種檢查**：基本檢查（空值、只有一個值）一定跑；分布偏移與極端值在設定檔寫 `checks.distribution: true` 時才跑。相關性在第三階段加上；在那之前，設定檔寫了 `checks.correlation`、`thresholds.corr` 會報錯。

---

## 1. 怎麼跑

```bash
cd <repo-or-worktree-root>
export SPARK_CONF_DIR=<Spark 設定目錄>      # 本機用 $PWD/conf/spark-local（見 local-spark-setup.md）

# 1. 複製範本，改成你的表
cp scripts/profile_feature_table.template.yaml my_profile.yaml

# 2. 算統計量、存 profile.json、畫報告
PYTHONPATH=src .venv/bin/python scripts/profile_feature_table.py run --config my_profile.yaml

# 3. 想換門檻：只重畫，不重跑 Spark
PYTHONPATH=src .venv/bin/python scripts/profile_feature_table.py render <輸出資料夾> --config my_profile.yaml
```

- 開 Spark 的方式同 `scripts/sampling_overrides_editor.py`：工具只給 `app_name: feature-profile`，其餘 Spark 設定（master、executor 記憶體、Hive metastore）全部來自 `SPARK_CONF_DIR` 目錄裡的設定檔，工具的設定檔裡沒有 Spark 區塊。要調 Spark 就改那個目錄。
- 跑完會印出報告位置。報告是單一頁面 `index.html`，不連網，可以單獨帶走。
- `render` 不給 `--config` 時，用 `profile.json` 裡存的門檻（也就是 `run` 當時的門檻）。`render` 不會改 `profile.json`。

### `--batch-size`

`run` 把特徵欄位分批，每批跑一趟 Spark 聚合、只讀自己那幾欄。預設每批 200 欄。上千欄的表一次聚合會讓執行計畫過大，每批太少又會多掃很多趟。預設值還沒在正式環境量過：第一次在真表上跑時，請記下欄數、期數、每期筆數、耗時，必要時換幾個 `--batch-size` 比較。

### 分布偏移與極端值要多跑多久

`checks.distribution: true` 時，Spark 多做三件事：

| 哪一趟 | 多做什麼 |
|---|---|
| 基本檢查那一趟 | 數值欄位多算 13 個分位數（`percentile_approx`），不多掃一趟 |
| 字串欄位的常見值 | 只讀最早一期，找每個字串欄位最常見的 20 個值；沒有字串欄位就幾乎不花時間 |
| PSI 分組筆數 | 所有期別再掃一趟，數每一期、每一組幾筆 |

報告〈資料範圍與判斷標準〉的「執行時間」會拆成這三段，方便和只跑基本檢查的耗時比較。

### `--accuracy`

分位數用 Spark 的 `percentile_approx` 估計，`--accuracy` 是它的精度，預設 10,000（Spark 的預設值，排名誤差約 1／10,000）。越大越準，也越耗 executor 記憶體與時間。預設值還沒在正式環境量過：第一次在真表上跑時，請記下耗時；記憶體不夠時先調小再試。

## 2. 設定檔

每一個鍵和「沒寫會怎樣」都寫在範本 `scripts/profile_feature_table.template.yaml` 裡，這裡只講容易踩到的：

| 鍵 | 要注意的事 |
|---|---|
| `table`、`time_col`、`key_cols` | 必填。`key_cols` 至少一欄 |
| `checks.distribution` | 必填，`true` 或 `false`：要不要跑分布偏移與極端值（多跑的時間見上一節）。第一階段的設定檔沒有 `checks`，會報「必填鍵 checks 沒寫」，補上 `checks:` 與 `  distribution: false`（或 `true`）兩行即可 |
| `exclude_cols` | 不是特徵、也不是主鍵的欄位（例如寫入時間）。不寫的話會被當成特徵檢查 |
| `time_range` | `start`、`end` 都含當期，可以只寫一個。直接和 `time_col` 比較 |
| `where` | 篩的不是分區欄位時，Spark 會掃全表，會變慢 |
| `thresholds` | 認 `null_ratio`、`psi`、`tail_ratio`、`tail_log_ratio`。沒寫的鍵用預設值。上一版的 `precision_max_abs` 已經拿掉，寫了會報錯，刪掉那一行即可 |

**開跑前會先檢查設定**：必填鍵沒寫、不認得的鍵、值的型別不對、表不存在、`time_col`／`key_cols`／`exclude_cols` 有不存在的欄。所有問題一次列完再結束，不會改一個、跑一次、再冒出下一個。只有「連 `table` 都沒寫」時不開 Spark、直接列出其他問題。

## 3. 報告怎麼讀

報告是一頁，左邊是目錄，最上面一行固定顯示表名、期間、每期筆數。段落依檢視項目排：

| 段落 | 用來做什麼 |
|---|---|
| 總覽 | 每個檢視項目有幾欄有事，點了跳過去 |
| 空值 | 每一期都幾乎是空值、部分期別幾乎是空值；另外列出有變動但沒達門檻的欄位，只供參考 |
| 只有一個值 | 整欄只有一個值、部分期別只有一個值、每期各只有一個值；另外列出值幾乎都相同（p1＝p99）的欄位，只供參考 |
| 分布偏移 | 每一期和最早一期（基準期）比的 PSI。分數值欄位、字串欄位兩張表；數值欄位附分位數走勢，字串欄位附各值占比 |
| 極端值 | 最離譜的那一期、那個值、p1～p99，以及被標了幾期 |
| 全部欄位 | 查單一欄位或一整族欄位；點欄名展開各期的總筆數、空值筆數、最小值、最大值，有跑分布時再加分位數與 PSI |
| 行動建議總結 | 把前面的結果整理成四種做法，每種都能複製欄名（一行一個） |
| 資料範圍與判斷標準 | 這次算的是哪張表、哪幾期、用了什麼門檻；型別不支援而沒檢查的欄位；設定檔原文 |

- 每一欄的「各期」是一個小長條圖：一期一根，由左到右是最早到最新，期別再多也一樣寬（超過 150 期時看不清單一期，點欄名展開明細）；滑鼠移上去看那一期的數字。
  - 空值的圖：越高越空，達門檻的是橘色。
  - 〈部分期別只有一個值〉的圖：橘＝那一期只有一個值，灰＝有變化，空白＝整期都是空值。
  - PSI 的圖：最左邊是基準期（0），越高差越多，達門檻的是橘色；高度到門檻的兩倍為止。
  - 分位數走勢：每一根是那一期的分布，淺色是 p1～p99、深色是 p25～p75、橫線是中位數。預設 log 刻度（每個數先換成 sign(x) × ln(1 + |x|)），金額這類長尾欄位才看得到整條分布；表上方可以切回一般刻度。整條跳一段，通常是換了單位或計算方式；慢慢移動，通常是客群在變。
  - 各值占比：每一根是那一期各值的占比，由下往上依基準期的占比排；顏色的意思寫在表上方。
  - 極端值的圖：高度是那一期兩側較大的 log 後倍數，同一側兩個條件都達門檻的是橘色。
  - 〈值幾乎都相同〉的圖：深灰＝那一期 p1＝p99。它只供參考，所以不用橘色。
- 表格點表頭可以排序；上方的篩選框可以篩欄名，頁首的篩選框會套到每一張表。「部分期別幾乎是空值」可以用「出事的期別」篩出某一期斷了哪些欄。

### 七種問題

「只有一個值」都是扣掉空值之後；某一期全是空值時，那一期直接略過。空值＝NULL、float／double 的 NaN 與 ±Infinity、字串的空字串。

| 問題類型 | 判斷標準（預設） | 設定鍵 |
|---|---|---|
| 每一期都幾乎是空值 | 每一期的空值比例都 ≥ 99% | `null_ratio` |
| 部分期別幾乎是空值 | 只有部分期別的空值比例 ≥ 99% | `null_ratio` |
| 整欄只有一個值 | 所有期別合計只有一個值 | — |
| 部分期別只有一個值 | 只有部分期別只有一個值 | — |
| 每期各只有一個值 | 每一期都只有一個值，但各期的值不同 | — |
| 分布偏移 | 有一期和基準期比的 PSI ≥ 0.25 | `psi` |
| 極端值 | 有一期、同一側同時符合：倍數 ≥ 10，而且 log 後倍數 ≥ 1 | `tail_ratio`、`tail_log_ratio` |

- 「每一期都幾乎是空值」「整欄只有一個值」不再判斷其他問題；「每期各只有一個值」不判斷分布偏移、極端值；其他問題可以同時成立。
- **PSI**：數值欄位用基準期的十分位數切成 10 組（每組含上界，相同的切點合併），字串欄位取基準期最常見的 20 個值各成一組、其他值一組，空值都另成一組。PSI ＝ Σ（本期占比 − 基準期占比）× ln（本期占比 ÷ 基準期占比），占比是 0 的組用 0.0001 代替。基準期＝這次讀到的最早一期，想換就改 `time_range` 或 `where`。基準期整期都是空值的欄位不比。
- **空值也算一組**，所以某一期空值突然變多，也會被標成分布偏移。表上的「變化主要來自」分得出來：扣掉空值再算一次 PSI，沒達門檻是「空值比例」，達門檻是「值的分布」。
- **極端值**：倍數＝最大值離 p99 的距離 ÷（p99 − p1），最小值那一側是 p1 離最小值的距離；log 後倍數是四個數先換成 sign(x) × ln(1 + |x|) 再算。只看倍數，金額這類長尾欄位幾乎都會被標；兩個一起看才排除得掉。p1＝p99 的那一期不判斷。為什麼是這兩個門檻，見設計文件附錄一。
- **值幾乎都相同**（p1＝p99、但不只一個值）只供參考，不算問題、不進總結。

### 行動建議總結的四種做法

| 做法 | 來自 |
|---|---|
| 可以排除：欄位沒有資訊 | 每一期都幾乎是空值、整欄只有一個值 |
| 請上游查這幾期的資料 | 部分期別幾乎是空值，而且跳幅 ≥ 10 個百分點；部分期別只有一個值；極端值，被標的期別不到一半（只列最離譜的那一期） |
| 確認分布為什麼變了 | 分布偏移；偏移的期別都已經列在「請上游查」的除外 |
| 看業務意義決定要不要留 | 部分期別幾乎是空值，但跳幅 < 10 個百分點；每期各只有一個值；極端值，一半以上的期別都被標 |

- 跳幅＝出事那幾期最低的空值比例 − 其他期別最高的空值比例。跳幅大，是那幾期突然空掉；跳幅小，是本來就很空、偶爾越過門檻。10 個百分點寫在程式裡（`UPSTREAM_JUMP_MIN`），不是設定鍵。
- 極端值的分界同樣寫在程式裡（`TAIL_LONG_SHARE`，一半）：只有少數幾期被標的像那幾期的資料錯了；大部分期別都被標的像欄位本來就長尾（例如資產）。
- 「請上游查」那一列會列出每一期要查哪些欄；「確認分布為什麼變了」依 PSI 第一次達門檻的期別分組，同一期開始變的多半是同一件事。每一期各有一個複製按鈕。
- 偏移的期別如果都已經列在「請上游查」（例如那一期斷掉、填了預設值），是同一件事，不再列一次。
- 不檢查 float32 精度：對 LightGBM 幾乎沒有影響，理由見設計文件〈一、目的〉的「不做的事」。

## 4. 輸出的檔案

```
data/profiling/feature_profile/<表名>_<YYYYMMDD_HHMMSS>/   # 或 output_dir 指定的位置
├── profile.json     # 統計量（不含判斷結果），render 只靠它重畫
└── index.html       # 報告
```

用新版 `render` 重畫上一版 `run` 的資料夾也可以：`index.html` 會換成新版，舊版的 `01-flags.html`、`02-basic.html`、`05-all.html`、`plotly.min.js` 不會被刪，也不再被連到，可以自己刪掉。

`profile.json` 存的是每一欄、每一期的總筆數、空值筆數、最小值、最大值；有跑分布時再加數值欄位的分位數，與 PSI 的分組方式和每期各組筆數。判斷結果每次畫報告時依門檻重算，所以換門檻只要 `render`。`schema_version` 不符時 `render` 會請你重跑 `run`。

只有基本檢查的 `profile.json`（第一階段的，或 `checks.distribution: false` 跑的）照樣能 `render`：〈分布偏移〉〈極端值〉〈值幾乎都相同〉會寫「這次沒有跑」。要看這幾段得重跑 `run`，`render` 不會補算。
