dataset pipeline 流程圖

node 層級的 DAG：誰產出什麼、誰吃什麼。對照 src/recsys_tfb/pipelines/dataset/pipeline.py::create_pipeline。 姊妹圖 training-pipeline.html、inference-pipeline.html； 資料表 schema 與跨 pipeline 的完整 lineage 見 data-lineage.html， 各 node 的設定與重跑範圍見 dataset.md。

框內是 node name，可以直接餵給 --from-node / --only-node（--list-nodes 印的也是這個名字）。 它跟函式名不一定相同——四個 build_*_model_input 共用同一個 build_model_input 函式， 對照見下方表格第二欄。刻意不畫：每個 node 都吃的 parameters（*_month_plan 不屬於這一類，它是 pipeline.py 宣告的真實 input）。 AST 掃過，本 pipeline 沒有「宣告了但函式沒讀」的參數——inference 圖上那種虛線邊，這裡沒有對應物。

流程圖

左→右為資料流向。三條主線分別是 key 選取（收哪些 row）、前處理（特徵怎麼編碼）、 組裝 model input（把前兩者接起來）。圖寬 2818px，視窗放不下時可在框內左右捲動。

讀圖重點

  • 前處理與抽樣是解耦的。fit_preprocessor_metadata 只吃 feature_table、不吃任何 keys——category mappings 只在 train 月份 fit， 換抽樣設定不會改變編碼結果。
  • 編碼只做一次。apply_preprocessor_to_features 產出的 preprocessed_feature_table 被四個 split 共用，不是每個 split 各編一次。
  • 四個 split 都有同一條規則，預設只有 val / test 在丟。有正例的 query group 全留，沒有正例的整組留下比例 r （dataset.*_zero_positive_group_ratio，ADR-0025 決定 3）。 預設 val / test 的 r ＝ 0（全丟：mAP 本來就排除它們）、train / train-dev 的 r ＝ 1（全留）。 四個 split 都在建表之前、在 keys 上做（filter_train_keys、filter_train_dev_keys、 filter_val_keys、filter_test_keys，ADR-0029 決定 4）—— 這樣落地的 keys 就是建表的輸入，粒度閘 B10 的「列數相等」四個 split 都成立。val / test 在 r > 0 時 keys 多一欄權重，建表時帶進 model input。
  • 四個 node 是增量的（圖上標「增量」）： select_test_keys、filter_test_keys、apply_preprocessor_to_features、 build_test_model_input 只處理尚未落地的月份，差集由 metastore 的 partition 清單得出（landed_months() 讀 existing_partition_values()，零掃描）。 train / train-dev / val 不是增量，一旦被執行就整批重算。加評估月份時省掉那次重算， 靠的是 --only-test-months 讓它們不被執行（它是 create_pipeline 的模式、 不是切片，見 ADR-0013）， 不是讓它們變成增量的。上面那條 test 鏈則帶不帶旗標都是增量的。理由與逃生口見 ADR-0002。
  • 增量是從哪來的：月份計畫。這四個 node 之所以只處理部分月份，是因為它們各吃一個 *_month_plan 輸入（圖上的 [P]）。這些 plan 由 pipelines/dataset/month_plans.py::build_month_plans 在 run 開始前一次算好、 注入 catalog（呼叫點是 __main__.py 的 dataset() 指令）——一次算好，是為了讓共用同一份 artifact 的 node 不可能對「這次涵蓋哪些月份」有不同看法。filter_test_keys 吃的是 test_keys_month_plan（跟選 key 同一份），它讀 label_table 的月份就是這次選 key 的月份。
  • 只有一條邊標「跨月讀回」。test_keys 的 catalog 條目只有 partition_filter: base_dataset_version，沒有鎖月份，所以讀回來是同一個 base version 底下的所有月份——即使 filter_test_keys 這次只寫了新的那個月 （dynamic partition overwrite）。build_test_model_input 因此必須自己再過濾一次 month_plan.to_process，否則下游 join 會把每個月都重建一遍，正好是 ADR-0002 要消掉的 ∝N 成本。train / val 讀的 keys 是這次 run 自己寫的，沒有這個問題—— 這就是為什麼只有 test 有自己的 wrapper node，其餘三個共用 build_model_input。
  • 圖上十六個產出裡有四個不落地。train_keys_unfiltered、train_dev_keys_unfiltered、 val_keys_unfiltered 與 test_keys_unfiltered 不在 catalog.yaml 裡，是 MemoryDataset（圖上虛線膠囊）；只有整組抽樣之後的 keys 落 Hive。
  • 閘在最前面。validate_data_consistency 是 Layer-2 資料閘 （B1 item coverage、B5 categorical dtype、B6 非數值特徵欄、 B7 carry/feature 撞名），只做檢查不產出資料，收集完問題一次中止， 避免抽樣與前處理白跑。代號意義的唯一真實來源是 core/consistency.py 的模組 docstring。

怎麼改這張圖

圖的真實來源是 docs/diagrams/dataset-pipeline.mmd（Mermaid，純文字）。 這頁內嵌的是它渲染出來的 SVG——改圖請改 .mmd，不要直接動這頁的 SVG，否則兩邊會分岔。

# 1. 編輯源檔
vim docs/diagrams/dataset-pipeline.mmd

# 2. 重新渲染（用系統 Chrome，不另外下載 chromium）
cd docs/diagrams
PUPPETEER_SKIP_DOWNLOAD=1 \
PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
npx -y @mermaid-js/mermaid-cli@10 -t neutral \
  -i dataset-pipeline.mmd -o dataset-pipeline.svg -b transparent

# 3. 把產出的 SVG 內容貼回這頁 <div class="plate"> 之間
#    （width="100%" 改成實際 px、max-width 改 none，文字才不會被縮小）
兩個實測過的坑：(1) .mmd 裡不要留「只有 %%、後面沒有字」的空註解行—— mermaid 不會把它當註解剝掉，會黏成 %%flowchart 然後報 parse error 在第 1 行，很難聯想；要空行就用真正的空行。 (2) 用 mermaid-cli@10 不要用 @11：同一張圖 v11 的新 renderer 產出 666 KB SVG （形狀改由 rough.js 畫，單條 path 灌到 30 KB），v10 是 43 KB。
