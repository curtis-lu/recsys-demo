evaluation pipeline 流程圖

node 層級的 DAG：誰產出什麼、誰吃什麼。對照 src/recsys_tfb/pipelines/evaluation/pipeline.py::create_pipeline。 姊妹圖 dataset-pipeline.html、training-pipeline.html、inference-pipeline.html； 資料表 schema 與跨 pipeline 的完整 lineage 見 data-lineage.html， 各 node 的設定與重跑範圍見 evaluation.md， 診斷產物的判讀見 evaluation-diagnosis.md。

框內是 node name，可以直接餵給 --from-node / --only-node（--list-nodes 印的也是這個名字）。 四個 diagnose_* 共用同一個生成器 make_diagnosis_node，node name 由它明設 __name__ 而來，對照見下方表格第二欄。 刻意不畫：每個 node 都吃的 parameters；只當過濾條件的 config（evaluation.snap_date、k_values、 各項 diagnosis.*.enabled）。--post-training 與預設（監控）模式的差別畫在兩處：來源那一格（換第一個輸入）， 以及診斷那一塊——registry 診斷與分頁只在 --post-training，監控模式換成 no_diagnosis_pages，兩個框各自標明。

流程圖

標「僅 --post-training」與「僅監控模式」的兩個框各只屬於一種模式，其餘兩種模式都有；--compare <key> 在兩種模式都追加比較那一框的三個 node；--compare-only <key> 只跑那三個加一個驗證 node。

讀圖重點

  • registry 診斷只在 --post-training。監控模式（預設，含 --compare）不組各項 diagnose_* 與 render_diagnosis_pages，報表沒有診斷入口（ADR-0018 決定 5）。generate_report 是位置綁定、六個必填輸入， 所以監控模式由 no_diagnosis_pages 供一份空清單：它什麼都不讀。不沿用 render_diagnosis_pages 是因為那個 要求每項 registry 診斷各一份帶名字的結果，監控模式一份都沒算。
  • 實線膠囊與虛線膠囊的分布跟直覺相反，而這決定了重繪要花多少錢。 四份診斷 JSON、evaluation_metric_ci、evaluation_report_aggregates 有 catalog entry（會落地）； 而 evaluation_metrics、baseline_metrics、evaluation_diagnosis_pages 沒有。 切片的停止條件是 can_load（＝檔案在不在），所以 --only-node generate_report 會沿著虛線那幾條一路把 prepare_eval_data、compute_metrics、compute_baseline_metrics 全部拉回來重跑全量 Spark，而實線那幾份直接讀舊檔。 generate_report 做成純函式本來就是為了「便宜重繪」的投資，這個缺口把它抵銷掉了。
  • 那些落地的 JSON，路徑只用 (model_version, snap_date) 當 key；設定指紋寫在檔內（#342）。 每份落地 JSON 帶 config_fingerprint，只涵蓋「算的」設定。改了算的設定再 --only-node generate_report， render_diagnosis_pages／generate_report 會在畫之前 raise，訊息指出哪個鍵變了、該 --from-node 哪個 node； 只改畫的設定（report.display.* 等）照常重繪。分類見 docs/pipelines/evaluation.md §7.2。
  • render_diagnosis_pages 的四條入邊是資料流（#342 起）。 簽章是 (parameters, *diagnosis_results)，畫的就是這四份結果；畫之前檢查第 i 個結果帶著 DIAGNOSES[i] 的名字、設定指紋與目前設定一致，不合就 raise。 同一組 inputs 另外買到兩件事：(1) 執行順序——拓樸排序只看 node.inputs，排在所有診斷之後才拿得到這次的結果； (2) 切片擴張——JSON 已落地時 --only-node render_diagnosis_pages 不重算（讀回後比對指紋）， 全新 model_version 時才自動往上補算。
  • 診斷抽樣只抽一次，下游共用。draw_diagnosis_sample_node 的產出被 compute_metric_ci 與各項診斷共用。各自重抽（同 seed）結果會相同，但那是 N 次全量掃描；更重要的是 「同一份樣本」本身是正確性性質——CI 與診斷講的必須是同一批 query，否則兩張圖對不起來。
  • 四項診斷由 registry 導出，形狀完全一樣。來源是 diagnosis.metric.contract.DIAGNOSES，node 函式由 make_diagnosis_node 生成。 加第五項＝新增一個子套件 ＋ registry 補一行，report_builder 零改動。 diagnose_model_capacity 是唯一宣告自己 INPUTS 的那個（吃 gain_ledger ＋ evaluation_item_ability，不吃共用抽樣）——所以不必為了它讓每項診斷都收寬簽章。
  • 使用者要關掉一項診斷，動的是 evaluation.diagnosis.<name>.enabled，不是改 DIAGNOSES。 兩者的差別在產物：enabled: false 仍會落地一份 {"enabled": false} 的 stub JSON（看得出來「這次刻意沒算」）； 從 registry 移除則連檔案都不會有（看起來像「這個版本還沒有這項診斷」）。前者是操作，後者是改版本。
  • 比較模式把「算」與「畫」壓在同一個 node。generate_comparison_report 自己跑兩次 compute_all_metrics 再組 HTML；標準模式是分開的兩段。 指標定義沒有第二份——兩邊都走 metrics_spark.compute_all_metrics，這裡跑的是裁切後的兩份母體， 語意上必須重算。但產物只有 HTML：catalog.yaml 沒有比較結果的 JSON， 所以 --only-node generate_comparison_report ＝ 兩次全量 metric。
  • eval_predictions 有 5 個消費者，但沒有 cache。它是 MemoryDataset（lazy plan）， compute_metrics／compute_baseline_metrics／compute_report_aggregates／ draw_diagnosis_sample_node／persist_eval_predictions 各自求值一次。 要不要 cache／早落地是刻意還沒做的決定（先觀測、量出熱點再優化），見 deliberate-non-goals.md。

怎麼改這張圖

圖的真實來源是 docs/diagrams/evaluation-pipeline.mmd（Mermaid，純文字）。 這頁內嵌的是它渲染出來的 SVG——改圖請改 .mmd，不要直接動這頁的 SVG，否則兩邊會分岔。

# 1. 編輯源檔
vim docs/diagrams/evaluation-pipeline.mmd

# 2. 重新渲染（用系統 Chrome，不另外下載 chromium）
cd docs/diagrams
PUPPETEER_SKIP_DOWNLOAD=1 \
PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
npx -y @mermaid-js/mermaid-cli@10 -t neutral \
  -i evaluation-pipeline.mmd -o evaluation-pipeline.svg -b transparent

# 3. 把產出的 SVG 內容貼回這頁 <div class="plate"> 之間
#    （width="100%" 改成實際 px、max-width 改 none，文字才不會被縮小）

# 想先看一眼再貼：渲成 PNG 直接開
npx -y @mermaid-js/mermaid-cli@10 -t neutral \
  -i evaluation-pipeline.mmd -o /tmp/check.png -b white -w 2400
沿用姊妹圖那兩個實測過的坑：(1) .mmd 裡不要留「只有 %%、後面沒有字」的空註解行—— mermaid 會把它黏成下一行然後在第 1 行報 parse error；要空行就用真正的空行。 (2) 用 mermaid-cli@10 不要用 @11：v11 的新 renderer 產出的 SVG 大一個量級。 本圖 v10 產出 70 KB、寬 3719 px。

不想裝工具的話：把 .mmd 全文貼到 mermaid.live， 或貼進任何 .md 的 ```mermaid 區塊讓 GitHub 直接渲染。
