evaluation pipeline 流程圖

node 層級的 DAG：誰產出什麼、誰吃什麼。對照 src/recsys_tfb/pipelines/evaluation/pipeline.py::create_pipeline。 姊妹圖 dataset-pipeline.html、training-pipeline.html、inference-pipeline.html； 資料表 schema 與跨 pipeline 的完整 lineage 見 data-lineage.html， 各 node 的設定與重跑範圍見 evaluation.md， 訓練側 Gain 帳本與條件化 SHAP 背景的判讀見 evaluation-diagnosis.md。

框內是 node name，可以直接餵給 --from-node / --only-node（--list-nodes 印的也是這個名字）。 刻意不畫：每個 node 都吃的 parameters；只當過濾條件的 config（evaluation.snap_date、k_values）。--post-training 與預設（監控）模式的差別只畫在來源那一格（換第一個輸入與母體表），其餘 node 一樣。

圖例

來源表（catalog 的 read_only Hive table） 不是表的輸入：直接造成「資料列」的 config 值 別的 pipeline 落地的版本化 artifact node（框內為 node name）
落地的 catalog 條目（Hive table / JSON 檔） MemoryDataset：catalog 沒這個名字，只活在這次 run 的記憶體 別的 pipeline／別的模式會吃的產物

本圖沒有姊妹圖那兩種形狀：沒有六角形的閘、也沒有失敗路徑終點。evaluation 的檢查都寫在 node 裡、標為前置檢查，不是獨立的閘 node：prepare_eval_data（label_table 重複 key，bug 10）、compute_baseline_metrics（lookback 視窗沒有歷史，bug 1）、generate_report（設定指紋不合，bug 2）、restrict_to_common（共同 query group 或 item 為空，B3）。 唯一獨立成 node 的檢查是 --compare-only 的第一個 node（指定的 snap_date 沒有資料就中止）。

流程圖

兩種模式的 node 一樣；--compare <key> 在兩種模式都追加比較那一框的六個 node；--compare-only <key> 跑那六個加一個驗證 node，共七個。

讀圖重點

  • #351 起 evaluation_metrics、baseline_metrics 落地成 catalog 條目，這決定了重繪要花多少錢。 evaluation_report_aggregates、evaluation_metrics、 baseline_metrics 都有 catalog entry（evaluation_metrics / baseline_metrics 是 JSONDataset，落地到 data/evaluation/<model_version>/<snap_date>/，皆含 config_fingerprint；report.sections.baseline: false 時 baseline 那份是 {"enabled": false, "config_fingerprint": ...} stub）。generate_report 的輸入因此全部落地（#532 拿掉了最後一個 沒有 catalog entry 的輸入，診斷頁清單）。切片的停止條件是 can_load（＝檔案在不在），所以 --only-node generate_report 不會自動補跑任何 node；也不會沿線把 prepare_eval_data、 compute_metrics、compute_baseline_metrics 拉回來重跑全量 Spark。 generate_report 做成純函式本來就是為了「便宜重繪」的投資，#351 之前這個缺口把它抵銷掉，補上後才真的便宜。
  • 那些落地的 JSON，路徑只用 (model_version, snap_date) 當 key；設定指紋寫在檔內（#342）。 每份落地 JSON 帶 config_fingerprint，只涵蓋「算的」設定。改了算的設定再 --only-node generate_report， generate_report 會在畫之前 raise，訊息指出哪個鍵變了、該 --from-node 哪個 node； 只改畫的設定（report.sections 的其餘鍵）照常重繪；report.display.primary_map_k 要從 resolve_display_ks 接續（比較報表另有 resolve_comparison_display_ks）。分類見 docs/pipelines/evaluation.md §7.2。
  • 比較鏈每一步都落地，報表只讀 JSON（#536）。比較模式的六個 node 裡， load_compare_predictions、restrict_to_common、compute_compare_metrics 跑 Spark； compare_to_source、resolve_comparison_display_ks、generate_comparison_report 不跑。 指標定義沒有第二份——兩邊都走 metrics_spark.compute_all_metrics， 跑的是裁切後的兩份母體，語意上必須重算，這一步就是 compute_compare_metrics。 它的四份結果、涵蓋率、比較結果與 K 截斷都有 catalog entry，所以 --only-node generate_comparison_report 純重畫，不重算任何指標。 「跟誰比」記在每份比較產物的 compare_source：換了比較對象或改了 prod_mapping 之後只重畫會被擋下， 建議 --from-node compute_compare_metrics；改 guardrail_recall_k／primary_map_k 從 resolve_comparison_display_ks 接續。
  • enriched_eval_predictions 由 prepare_eval_data 直接落地，下游全部讀表。 join 只算這一次，寫進這個 model_version 本月的 partition（dynamic partition overwrite）； 原本另外把它落地的獨立 node 已刪除（#352）。compute_metrics／compute_baseline_metrics／ compute_report_aggregates／restrict_to_common 都各自把這張 Hive 表（這個 model_version 評估過的所有月份）讀回，再用 restrict_to_current_eval_partitions 篩回本次評估日期（一個或多個；ADR-0018 決定 1），並逐日期比對分區自帶的設定指紋（#374）。--compare-only 沒有 prepare_eval_data，直接讀回同一張表這個 model_version 已寫過的 partition。

怎麼改這張圖

圖的真實來源是 docs/diagrams/evaluation-pipeline.mmd（Mermaid，純文字）。 這頁內嵌的是它渲染出來的 SVG——改圖請改 .mmd，不要直接動這頁的 SVG，否則兩邊會分岔。

# 1. 編輯源檔
vim docs/diagrams/evaluation-pipeline.mmd

# 2. 重新渲染（用系統 Chrome，不另外下載 chromium）
cd docs/diagrams
PUPPETEER_SKIP_DOWNLOAD=1 \
PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
npx -y @mermaid-js/mermaid-cli@10 -t neutral \
  -i evaluation-pipeline.mmd -o evaluation-pipeline.svg -b transparent

# 3. 把產出的 SVG 內容貼回這頁 <div class="plate"> 之間
#    （width="100%" 改成實際 px、max-width 改 none，文字才不會被縮小）

# 想先看一眼再貼：渲成 PNG 直接開
npx -y @mermaid-js/mermaid-cli@10 -t neutral \
  -i evaluation-pipeline.mmd -o /tmp/check.png -b white -w 2400
沿用姊妹圖那兩個實測過的坑：(1) .mmd 裡不要留「只有 %%、後面沒有字」的空註解行—— mermaid 會把它黏成下一行然後在第 1 行報 parse error；要空行就用真正的空行。 (2) 用 mermaid-cli@10 不要用 @11：v11 的新 renderer 產出的 SVG 大一個量級。 本圖 v10 產出 84 KB、寬 5995 px。

不想裝工具的話：把 .mmd 全文貼到 mermaid.live， 或貼進任何 .md 的 ```mermaid 區塊讓 GitHub 直接渲染。
